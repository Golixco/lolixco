# Mission 7A — Current Catalog and Ingestion Architecture

## Executive Summary

Lolixco currently operates on **`demo-catalog-v1`**, consisting of exactly **17 landscape demo edits** (IDs `0` through `16`) generated procedurally in [`src/data/edits.ts`](file:///home/vuld0/Lolixco/src/data/edits.ts). This catalog is tightly bound to:
1. Pure client-side discovery search and category filtering in [`src/data/searchEngine.ts`](file:///home/vuld0/Lolixco/src/data/searchEngine.ts) and [`src/data/fandoms.ts`](file:///home/vuld0/Lolixco/src/data/fandoms.ts).
2. A deterministic Python recommendation service in [`server/recsys/`](file:///home/vuld0/Lolixco/server/recsys/) validated against [`server/recsys/catalog_snapshot.json`](file:///home/vuld0/Lolixco/server/recsys/catalog_snapshot.json).
3. A format-aware feed composition engine in [`src/data/feedComposition.ts`](file:///home/vuld0/Lolixco/src/data/feedComposition.ts) that differentiates landscape videos from portrait Shorts.
4. Static media assets validated by [`scripts/check-assets.mjs`](file:///home/vuld0/Lolixco/scripts/check-assets.mjs).
5. The content validation engine in [`scripts/validate-content.mjs`](file:///home/vuld0/Lolixco/scripts/validate-content.mjs) wired into CI via `npm run check:content`.

This document audits what functions well today and identifies the architectural adaptations required to ingest genuine owner-supplied media (~50 landscape videos and ~20 portrait Shorts).

## 1. Existing Catalog Components

### 1.1 Live Frontend Catalog (`src/data/edits.ts`)
- **Structure:** Contains 17 edits generated by mapping 17 titles across 6 categories (`Cinematic`, `Gaming`, `Anime`, `Movies`, `Series`, `Phonk`).
- **IDs:** Contiguous integers `0` through `16`.
- **Media References:** All 17 edits reference SVG posters (`/media/art-0.svg` to `/media/art-16.svg`) and a shared silent motion study video (`/media/motion-study.webm`).
- **Creator Metadata:** Hardcoded to `"Lolixco demo"`.
- **Format:** `format?: ContentFormat` exists on the TypeScript `Edit` interface, but is omitted from the 17 records, defaulting deterministically to standard landscape `"video"`.
- **Fandom IDs:** `fandomIds?: string[]` exists on the TypeScript `Edit` interface, but is omitted from the demo items.

### 1.2 Taxonomy and Fandom Registry (`src/data/fandoms.ts` & `src/types/content.ts`)
- **Categories:**
  - `CanonicalCategory`: `"Anime" | "Movies" | "Series" | "Multifandom" | "Gaming" | "Phonk"`.
  - `LegacyCategory`: `"Cinematic"` (reserved strictly for backward compatibility with initial demo items).
- **Fandom Registry (`FANDOM_REGISTRY`):**
  - Explicit registry with 5 registered fandoms:
    1. `jujutsu-kaisen` (Anime)
    2. `demon-slayer` (Anime)
    3. `spider-man` (Movies)
    4. `valorant` (Gaming)
    5. `doom` (Gaming)
  - Helper functions: `getFandomsForCategory()`, `getFandomById()`, `isFandomCompatibleWithCategory()`.

### 1.3 Feed Composition (`src/data/feedComposition.ts`)
- Pure, deterministic compositor separating:
  - `video_row`: Recommended Edits, More to Discover (contains landscape videos only).
  - `shorts_shelf`: Curated Shorts (contains portrait Shorts only).
- **Critical Invariant:** If `catalog` contains 0 Shorts (`isShort(edit) === false` for all edits), the Shorts shelf is **completely omitted** from the DOM.
- **Current Production State:** With exactly 17 landscape edits and 0 shorts, the home feed renders video discovery rows only.

### 1.4 Search Engine (`src/data/searchEngine.ts`)
- Evaluates queries with exact hashtag tokenization (`#tag`), title matching, topic tag matching, and category filtering.
- **Privacy Enforcement:** Creator metadata weight is strictly `0.00` (creator identities are completely excluded from public search ranking).

### 1.5 Media Playback
- **Landscape Video Player (`src/components/video/VideoPlayer.tsx`):**
  - Supports A-B looping, picture-in-picture, fullscreen, timeline scrubbing, volume memory, and playback error recovery.
  - Automatically pauses when modal overlays (e.g. ShortsViewer) become active.
- **Portrait Shorts Viewer (`src/components/shorts/ShortsViewer.tsx`):**
  - Fullscreen vertical modal overlay with vertical swipe / arrow key navigation, loop playback, hashtag exit navigation, and error retry state.

## 2. Python Recommendation Engine Contract (`server/recsys/`)

The Python recommendation service and test suite enforce strict contracts that must be preserved:

### 2.1 Catalog Snapshot Drift Check (`export_catalog.py`)
- Evaluates `catalog_snapshot.json` against `src/data/edits.ts` using Node's TypeScript loader.
- **Strict Whitelist (`ALLOWED_RECORD_FIELDS`):**
  ```python
  ALLOWED_RECORD_FIELDS = {
      "id",
      "title",
      "category",
      "tags",
      "description",
      "creator",
      "poster",
      "source",
      "duration",
      "trending",
  }
  ```
- **Constraint:** If new fields such as `format` or `fandomIds` are serialized in `src/data/edits.ts` without an intentional schema version bump, `check_catalog_drift` will flag unexpected fields and fail CI.

### 2.2 Category Validation (`types.py`)
- `CANONICAL_CATEGORIES` in `types.py` is currently defined as:
  ```python
  CANONICAL_CATEGORIES: tuple[str, ...] = (
      "Cinematic",
      "Gaming",
      "Anime",
      "Movies",
      "Series",
      "Phonk",
  )
  ```
- Notice that `Multifandom` is defined in frontend `src/types/content.ts` but is not yet in Python `CANONICAL_CATEGORIES`.

## 3. Ingestion and Validation Engine (`scripts/validate-content.mjs`)

The validation foundation provides authoritative schema validation and three distinct operational workflows:
1. **Metadata Preparation Mode (`--mode metadata`):** Validates manifest schema, taxonomy, ID range rules, string constraints, and declared aspect ratios without requiring media files to be present on disk. Explicitly reports asset verification as `SKIPPED`.
2. **Asset Verification Mode (`--mode assets`):** Verifies that local asset paths resolve strictly inside `public/media/` or `public/brand/`, confirms file existence and non-zero size, and checks header signatures without reading full video files into memory. Flags remote URLs.
3. **Publication Readiness Mode (`--mode publish`):** Requires clean metadata, clean staged assets, approved editorial review (`reviewStatus: "approved" | "published"`), and documented rights clearance (`rightsCleared: true`). Reports ffprobe stream inspection status.

## 4. Adaptations Required for Real Content Ingestion

| Subsystem | Current State | Required Adaptation for Real Ingestion |
| :--- | :--- | :--- |
| **Catalog IDs** | Integers `0-16` | Retain `0-16` for demo items. Ingested landscape videos use `100-199`; Shorts use `200-299`. |
| **Shorts Content** | 0 Shorts | Prepare manifest template and validation for ~20 portrait Shorts without fabricating dummy entries. |
| **Taxonomy** | 5 fandoms, 6 categories | Support `Multifandom` category, allow owner to submit additional registered fandoms. Prohibit `Cinematic` for new IDs. |
| **Asset Formats** | SVG, PNG, WebM | Expanded streaming header verification for MP4, WebP, JPEG, and validate 16:9 vs 9:16 aspect ratios. |
| **Metadata Ingest** | Hardcoded array in `.ts` | Owner-friendly JSON manifest with JSON Schema validation and separated private editorial fields. |
| **Recsys Sync** | Hardcoded 10-field check | Document clean migration path from `demo-catalog-v1` to `catalog-v2` when real content arrives. |
